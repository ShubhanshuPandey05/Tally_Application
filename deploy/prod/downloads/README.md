# deploy/prod/downloads

What Caddy serves at `/downloads/*`, and where the API reads `manifest.json`
from to answer "is this client current?" inline on every response.

Nothing here is built by the compose stack. Stage it before or after `up`:

```
manifest.json                        generated by `python run.py publish`
TallyFlowConnector-Setup-<v>.exe     built on Windows by `python run.py connector`
TallyFlow-<v>.apk                    built by `python run.py release <api-url>`
```

Two rules that matter:

**`manifest.json` is generated, never edited.** `run.py publish` measures
version, SHA-256 and size from the bytes actually being served here. A
hand-typed checksum ships an update every client refuses, and the refusal looks
like a broken updater rather than a bad manifest.

**An empty directory is a working deployment, not a broken one.** A missing or
unreadable manifest yields "no opinion" on versions rather than "you are out of
date" — a config mistake must never be able to lock a fleet out of their own
books. The site's download links will 404 until the artefacts are staged, and
nothing else changes.

The directory is mounted read-only into both `api` and `caddy`, so publishing a
new installer means copying files here, not rebuilding an image.
